# OpenQSE QRI Session 01 Main Points

Source: `openQSE-qri-session-01-transcript.docx`

## Main Points

- The session aligned the group around quantum resource interface scope for HPC environments.
- A quantum resource should usually mean more than the QPU alone; it includes classical control, preprocessing, access, and service components needed to make the QPU usable.
- Availability, health, calibration, authentication, cost, accounting, and queue behavior make quantum resources different from conventional HPC resources.
- Workload managers need availability, usage, and policy-relevant status, while detailed device telemetry belongs in monitoring, analytics, and operations systems.
- QDMI, QRMI, and QFW were discussed as relevant interface and execution layers.
- Benchmarking was identified as the bridge from interface discussion to evidence.

## Conclusions

- The group should not finalize a standard immediately.
- The path forward should gather stakeholder requirements, propose interface behavior, test it in real systems, and refine toward a shared specification.
- Future artifacts should include a testbed, usage-pattern data, interface comparisons, resource specifications, and operations/monitoring requirements.
