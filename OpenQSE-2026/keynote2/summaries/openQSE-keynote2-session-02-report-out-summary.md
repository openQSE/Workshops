# OpenQSE Keynote 2 Session 02 Report-Out Summary

Source transcript: `openQSE-keynote2-session-02-transcript.docx`

## Main Point

Session 02 was Laura Schulz's keynote on why quantum-HPC success depends on ecosystem design, not just qubit technology. The talk connected the new DOE quantum supercomputing blueprint, Genesis/American Science Cloud federation, Exascale Computing Project lessons, and user personas. The main message was that OpenQSE needs to prepare software, access, governance, identity, workflow, and support structures before early fault-tolerant hardware arrives.

## What Was Discussed

- DOE's quantum supercomputing blueprint targets at least 100 logical qubits and 10^4 to 10^5 hard logical operations by 2028.
- The ecosystem must be ready to use that hardware, including programming expertise, system software, compilers, standards, benchmarks, and support.
- Quantum chemistry embedding and fragmented workflows were highlighted as likely early success areas.
- The Exascale Computing Project was used as a model for preparing software and user communities before major hardware arrives.
- Genesis and American Science Cloud federation raise integration issues around identity, trust, data movement, policy, and distributed resource access.
- Laura organized the problem into infrastructure, technical, and community ecosystems.
- User personas were emphasized as essential because first-wave power users and later domain scientists will need different levels of abstraction.

## Key Takeaways

- A hardware demonstration alone will not create scientific impact.
- OpenQSE should build the usable ecosystem before the first major early fault-tolerant systems arrive.
- Federation is both a technical problem and a policy/administration problem.
- Quantum-HPC workflows must align with HPC and AI infrastructure instead of becoming a separate silo.
- Requirements should be tied to specific user personas and user teams.

## Presentation Bullets

- Quantum advantage requires ecosystem readiness.
- Prepare the software, access, standards, benchmarks, and support layer before 2028-class hardware appears.
- Federation must handle identity, trust, policy, data, scheduling, and cross-institution workflows.
- Learn from ECP: software readiness and long-term support must be planned early.
- Define user personas so OpenQSE can support both hardware-level experts and domain scientists.

## Suggested Next Actions

- Expand quantum user persona work.
- Track Genesis decisions that affect quantum integration.
- Study ECP lessons for OpenQSE ecosystem planning.
- Identify which data governance and security requirements belong in architecture versus policy.
- Increase OpenQSE visibility in the broader DOE quantum community.
