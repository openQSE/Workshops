# OpenQSE Keynote 2 Session 02 Main Points

Source: `openQSE-keynote2-session-02-transcript.docx`

## Main Points

- Quantum-HPC success depends on ecosystem readiness, not qubit technology alone.
- DOE's quantum supercomputing blueprint set a 2028 target around early fault-tolerant capability, including at least 100 logical qubits and 10^4 to 10^5 hard logical operations.
- OpenQSE should prepare software, access, workflow, governance, identity, benchmarking, and support layers before early fault-tolerant hardware is broadly usable.
- Quantum chemistry embedding and fragmented workflows were highlighted as likely early success patterns for quantum-HPC integration.
- Genesis and American Science Cloud federation raise technical and policy requirements around identity, trust, data movement, scheduling, and cross-institution access.
- User personas are needed because hardware-level experts, early power users, and later domain scientists will require different abstraction layers and support models.

## Conclusions

- A hardware demonstration alone will not create scientific impact if the surrounding ecosystem is not ready.
- OpenQSE should learn from the Exascale Computing Project by planning software readiness and long-term support early.
- Federation should be treated as both a technical architecture problem and a governance problem.
- OpenQSE should stay aligned with HPC and AI infrastructure work rather than creating isolated quantum-only solutions.
